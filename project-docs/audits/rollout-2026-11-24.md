## Rollout S: the moments

Before: one trigger, the summary's Done button, after the third on-time
departure ever, every 90 days, no launch gate. It was a real good result but
asked from a button tap (5.6.1 risk), over Home as the summary slid away, and
only from the third on-time morning, so most installs never reached it.

Now (`ReviewPromptService.isGoodMoment`, `requestsReview(after:isClear:)`):

1. **A real departure left on time** (within the existing minute of grace,
   `DepartureRecord.wasOnTime`), 3 s into its summary. This is the app's core
   action finished with its promised outcome. A typical user runs their first
   real morning the day after setup, which is their 2nd or 3rd session, and
   the plan is padded by their pace answer so that morning is designed to end
   on time. From then on every on-time morning is a candidate, so the ask
   comes at the first on-time morning from launch 2 instead of the third.
   The app records no outcome analytics, so the on-time share is not known.
2. **A practice run finished with every step done**, 3 s into its summary
   ("Practice done."). An extra: most try-outs happen in session 1, which the
   launch gate blocks, so this mostly catches a later evening try-out.

Never asked: late mornings, practice runs with a skipped step, a summary
reopened more than 30 minutes after walking out (a relaunch, not the
moment), setup, or from any button.

Gates, kept exactly: no ask before the 2nd launch (counted once per process
when the window first appears, so a background launch for a Watch tap is not
a session), 30 days between calls stamped when the call is made (the 1.0.3
key `reviewLastAskedAt` is reused, so an install asked by 1.0.3 keeps its
cooldown), Settings' "Rate Shoes On" ends the passive asks (it now records
that), "Send feedback" never does. After the 3 s wait the ask is skipped
unless the summary is still on screen, the app is active, that same run is
still the summary with no run started over it, and `rating_prompt` is not
"off". The summary is a full-screen cover that nothing in the app presents
over, so those checks cover every sheet, alert and paywall. No enjoyment
question, no pre-prompt, no incentive. No analytics capture exists in this
app, so there is no `rating_asked` event to log.

## Held for Jack

1. **CP1, the trial reminder for an Ask to Buy trial approved later.** The
   day-5 reminder is scheduled only when the purchase call returns Pro; an
   approval that lands later through the delegate never schedules it.
   Recommendation: yes, schedule it from the entitlement (active trial that
   will renew, no reminder stored, two days before expiry at 10 AM) on any
   customer-info update, because it also covers a trial restored on a new
   phone. Held because it changes when the trial reminder is scheduled.
2. **Product calls from the audit** (not bugs, listed in
   `state-machines-2026-11-24.md`): leave alerts after "End without leaving",
   a practice run left open blocking the alert start, a second departure
   after editing today's leave time, the alert window shrinking with many Pro
   routines, and a trial reminder after a cancel made outside the app.
